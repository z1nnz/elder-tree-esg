# 生命樹庭園三維資產與動畫證據

## 本次目標

把資料驅動的二維生命樹進一步發展為獨立、全螢幕的三維生命樹庭園，先完成可重現模型、固定紀念掛點、資料驗證與枝葉風動垂直切片，再進行 Flutter 行動平台串接。

## 已產出的可重現資料

- 建模工具：Blender 5.2.1 LTS
- 場景工具：Unity 6000.0.82f1，安裝與專案驗證進行中
- 建模腳本：`tools/blender/build_life_tree.py`
- 可編輯母稿：`art-source/blender/生命樹庭園_母稿.blend`
- Unity 模型：`apps/life-tree-unity/Assets/Art/Generated/生命樹庭園.fbx`
- 通用交換模型：`apps/life-tree-unity/Assets/Art/Generated/生命樹庭園.glb`
- 固定視角檢查圖：`apps/life-tree-unity/Assets/Art/Generated/生命樹庭園_品質預覽.png`

目前模型階層包含一個主幹、八根獨立主枝、十六組前後葉冠、五根可見樹根及十二個固定紀念掛點。模型由固定種子與固定參數重建，掛點名稱與序號不因重跑改變。

## 主要負責人決策與整合範圍

1. Flutter 保留主要產品操作與無障礙文字，Unity 只負責全螢幕生命樹庭園，不重寫整套 App。
2. 採 Blender 母稿、FBX 遊戲資產、Unity 場景三層管線；資產可重建且保留來源，不只提交無法追溯的二進位檔。
3. 十二個紀念掛點使用穩定序號；同一後端成果不因每次開啟而改變位置。
4. Unity 只顯示 Flutter 由 API 讀回的成長與成果，不在本機製造成長進度。
5. 非必要風動在降低動態效果時完全停止；Flutter 二維生命樹保留為失敗與低階裝置替代。
6. 第一版低多邊形樹冠只作為可運作骨架，仍需提升樹冠輪廓、葉片層次、枝幹表面與正式紀念物，不將固定視角圖宣稱為最終美術。

## Unity 真實建置與測試

- Unity 6000.0.82f1 ARM64 編輯器已安裝，專案以 Metal 圖形裝置實際匯入 FBX、編譯 C#、建立場景並擷取 768 × 1024 畫面。
- 第一輪實際建置發現 C# 空狀態分支未賦值，修正後編譯通過。
- 第一張 Unity 實景發現 FBX 公尺／公分倍率造成樹縮成 1/100；場景以明確的 100 倍作者根節點修正，成長控制器改成保留作者比例。
- 自動建場實際核對 8 根主枝、16 組葉冠與 12 個固定掛點，輸出場景成功。
- Unity 編輯器測試 4／4 通過：接受有效資料與穩定掛點、拒絕重複掛點、拒絕超出六階段的本機成長資料，並證明降低動態會把主枝恢復到作者基準姿勢。
- [Unity 生命樹庭園實景](screenshots/life-tree-unity-garden.png)由場景相機直接渲染，不是 Blender 固定視角圖；仍不是手機效能或最終美術證據。
