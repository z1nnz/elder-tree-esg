## 這次真正驗證了什麼

這不是互相回傳假資料的前端展示。測試啟動真正編譯後的後端服務、HTTP 路由、資料驗證管線與隔離 PostgreSQL 資料庫，依序呼叫正式網頁客戶端及 Flutter 的 `ApiClient`／`AppController`。

| 流程 | 實際斷言 |
| --- | --- |
| 共創夥伴提案、送審、平台發布 | 建立據點旅程，取得已發布旅程編號；其他組織成員產碼被拒絕，狀態 403。 |
| 網頁產生到場碼 | 伺服器回覆有效期間 60 秒；不是測試延長的有效期間。 |
| 手機解鎖與完成 | 不附見證不能完成；額外未知巢狀欄位由真正 HTTP 管線拒絕，狀態 400。 |
| 手機送出有效見證與重送 | 完成成功，同一紀錄編號不變；重新讀取生命樹，成長合計只增加 12。 |
| 自願開啟回饋 | 領取碼有效 5 分鐘；網頁彙總此時為 1 次到場、0 次領取。 |
| 網頁同時送出兩次核銷 | 一次首次核銷、另一次回覆先前已核銷；兩者原領取時間相同，彙總為 1 次到場、1 次領取。 |
| 重新啟動手機測試程序讀取 | 正式客戶端讀到已領取紀錄，再次申請碼被拒絕；資料庫仍只有一筆到場紀錄。 |

## 隔離與證據界線

- 僅接受本機 `localhost`／`127.0.0.1`、名稱為 `venue_acceptance_*` 的專用資料庫，拒絕正式模式；HTTP 使用本機動態連接埠。
- 每次產生不同的四個測試身分、組織及旅程；結束後只清除該次建立的資料並關閉服務，不清空專案資料庫。
- `DEMO_MODE=false`，所有資料路由都走持久化資料。只在測試程序替換登入身分驗證，且限定本次四個測試身分；組織權限與平台管理者檢查仍走真實資料。
- 不修改正式驗證守衛、不開放正式服務使用測試標頭登入。這不等於 Firebase 登入驗收。
- 位置為明確標記的合成座標，不是實際 GPS。這套測試也沒有啟動手機相機或操作網頁畫面；不能稱為實體跨裝置掃碼通過。
- 短效測試碼只在程序環境及父子程序資料管線內傳遞；失敗輸出遮蔽碼值，不建立使用者活動、合作、消費或植樹成果。

## 發現的問題與修正

### 避免混用示範資料與真實資料

最初開啟示範模式時，寫入確實進入資料庫，但生命樹讀取仍由既有示範路由回傳固定數字，成長斷言因此失敗。改用非示範模式與測試限定身分後，真正讀回的成長差值為 12。沒有放寬斷言、增加正式登入後門或改動加分規則。

後端的前綴、跨來源設定與巢狀資料驗證抽出成共用啟動函式，避免驗收服務省略正式資料驗證。測試讀取 Nest 編譯產物，保留依賴注入及資料欄位中繼資料，不用缺少這些資訊的測試轉譯取代。

### 相機啟動、釋放與背景狀態

回歸測試重現：等待相機權限時關閉再重開，會在第一個工作階段尚未釋放前啟動第二個，晚到的舊清理可能關閉新鏡頭。現在同一原生相機的後續工作階段必須等待前一次啟動及釋放完成。

另一個問題是 App 進入背景後可能不再繪製下一幀，僅要求父畫面移除相機，不能保證立即停用原生資源。相機現在直接監聽隱藏／暫停／分離狀態並釋放；回到前景不自動重啟。權限視窗造成的短暫非互動狀態不當作離開。

[相機回歸測試](../../apps/mobile/test/venue_witness_test.dart)使用可延遲的相機平台替身，核對 `啟動第一個 → 停止 → 釋放 → 啟動第二個`、背景釋放及回前景不重啟。修正前可重現同時出現兩次啟動，修正後通過。這是資源排程測試，仍不能代替實機權限視窗及相機驅動驗收。

## 執行結果與重現

本機環境為 Flutter 3.41.7、隔離 PostgreSQL 16；沒有連接可用的實體手機。2026-08-28 14:31 的最後一輪跨端驗收通過，整體約 8 秒；之前同日兩輪也通過，最後一輪再加入手機重送不重複成長的斷言。

```sh
# 前置：已安裝 Node／Flutter 依賴，並在專用本機 PostGIS 資料庫套用遷移。
npm run build:contracts
npm run build --workspace @elder-tree/api
VENUE_ACCEPTANCE_DATABASE_URL=postgresql://venue_test:venue_test@127.0.0.1:5432/venue_acceptance_local \
  npm exec --workspace @elder-tree/admin-web -- vitest run src/lib/venue-live.integration.test.ts
```

若 Flutter 不在路徑，可另設定 `FLUTTER_BIN` 為執行檔完整路徑。一般 `npm test`／`flutter test` 沒有專用服務時明確略過此測試；持續整合獨立建立 `venue_acceptance_ci`，以 PostGIS 執行完整遷移後強制執行跨端流程，不依賴正式帳號或私密資料。

乾淨環境須先建置共用契約套件，再建置後端；已將此順序加入持續整合與上述指令，不依賴本機先前留下的 `dist`。

- 全倉 Node 型別檢查通過；一般 Node 測試 45 項通過、32 項資料庫測試及 1 項跨端測試明確略過，跨端測試另行執行通過。
- 手機靜態檢查無問題；全套 35 項通過、1 項需獨立服務的測試略過；該測試在跨端流程內由兩個 Flutter 程序真正執行。
- 本機另外執行完整後端資料庫測試得到 59 項通過、1 項失敗：本機 PostgreSQL 缺少 PostGIS 的 `geography` 型別，影響既有城市探索距離測試。沒有移除該測試、改成模擬距離或把它列為通過。本機跨端資料庫採 schema 建立，不冒充完整遷移驗證；新持續整合使用 PostGIS 補足這項環境界線。
- 前一提交 `6861ddf` 的八項持續整合已通過；本次新增內容的完整遷移、Android／Apple 建置及跨端結果以 #42 最新提交的檢查為準，不沿用前一提交的綠燈。
