# 照片見證中繼資料修正

## 問題

`apply_rules` 原本以 `image_url is not None` 回報 `exif_removed`：網址輸入即使因缺少辨識金鑰而完全未下載處理，也會標記已清除；Base64 輸入即使確實清理，也會回報未清除。

## 修改與驗證

規則計算預設不宣稱影像已清理；只有 `verify_photo` 的影像清理與分類路徑完成後，才將結果標記為已移除 EXIF。

執行 `services/ai-verifier/.venv/bin/python -m pytest -q`：12 項通過。新增覆蓋：未處理網址不能宣稱已清除、網址／Base64 清理路徑完成後正確回報，以及用記憶體內合成 JPEG 驗證實際清理函式移除 EXIF。模型呼叫與網址下載在路徑測試中使用替身，沒有傳送照片至外部供應商。

## 當前服務限制

本機預設 API `127.0.0.1:4100` 與辨識服務 `127.0.0.1:4400` 健康查詢均未連通。本輪沒有啟動或部署服務，也沒有宣稱真實 AI 辨識已通過。健檢執行時主動移除該子程序的金鑰環境變數以避免日誌顯示片段；因此其中的金鑰警告不代表電腦或其他服務沒有設定金鑰。

完整驗收仍需服務啟動、實際授權上傳、外部辨識、後端回寫及手機結果呈現。本輪只修正見證欄位的真實性，不替代端到端驗收。
