# 到場見證與共創夥伴台：介面驗收紀錄

日期：2026-08-28。分支：`codex/venue-witness-redemption`。[合併請求 #42](https://github.com/z1nnz/elder-tree-esg/pull/42) 仍為草稿；本文是網頁端階段成果，不代表手機串接、正式發布、實機掃描或場域試辦已完成。

## 問題、選擇與實作

場域人員需要兩種不同操作：向成員展示短效到場碼，以及讀取成員的領取碼後登記自願回饋。兩者不能混用，掃描成功也不能直接當作回饋已交付。

採用「介面匠心」：沿用品牌深林綠 `#176B4A`、墨色 `#17201C`、霧白 `#F5F7F5`、白色工作區；宋體任務標題搭配既有無襯線操作文字。主畫面以一個明確的現場操作區為核心，旁邊保留旅程條件與彙總成效。辨識重點是「為共同旅程留下足跡」，不是廣告看板或虛構影響數字。

窄版將說明移到操作區下方；使用容器查詢，避免嵌在夥伴台內時只依整個瀏覽器寬度判斷。這是新增工作台，沒有同功能舊版截圖可作前後比較；既有登入與提案頁仍見[前一輪紀錄](issue-39-partner-workspace-evidence.md)。

「網頁體驗巡檢」檢查後修正了以下問題：

- `apps/admin-web/src/components/venue-station.tsx`：標題層級、開啟焦點、掃描輸入不可透過 Enter 自動核銷、重複領取與不確定結果分開呈現。
- `apps/admin-web/src/components/partner-workspace.tsx`：收起工作台後恢復到原旅程入口；只有已核准且要求到場見證的提案顯示入口。
- `apps/admin-web/src/components/venue-station.module.css`：容器窄版回流、至少 48px 按鈕高度、可見焦點與切換按鈕滑入狀態。不增加入場動畫或限制文字比例。

## 互動與安全界線

- 到場碼由使用者明確開啟，最長依伺服器時間顯示 60 秒。扣除請求耗時，使用單調時鐘倒數；過期即隱藏，續碼失敗須手動重試。
- 離開分頁即收起碼與鏡頭；晚到回覆不重新顯示舊碼。相機權限在離開後才批准時也會停止串流。
- 領取碼掃描／貼上只填入欄位；鍵盤式掃描器附帶的 Enter 不會核銷，必須另選「確認核銷」。重複回覆顯示「先前已領取，請勿再次交付」。
- 到場碼和領取碼在本機編解碼，沒有第三方產碼網站。內容不寫入網址或本機儲存。
- 未讀到成效顯示「—」與重試，不假裝為零。不領取回饋不影響已完成的旅程或年輪進度。
- 現場短效碼不能排除即時轉傳或定位偽造，不能單獨證明共同在場、消費、健康改善或真實植樹；限低風險試辦。

## 依賴與待辦

新增執行期套件固定為 `qrcode@1.5.4`、`@zxing/browser@0.1.5`（鎖檔解析其相容解碼器為 `@zxing/library@0.21.3`）。依據[產碼套件文件](https://github.com/soldair/node-qrcode)與[瀏覽器解碼器文件](https://github.com/zxing-js/browser)使用本機產碼與可停止的相機串流。另新增測試環境；鎖檔無既有版本變更或套件移除。

`npm audit` 當次回報 20 項風險（14 高、6 中），列名涉及既有 Next、Nest、Prisma、Firebase 等依賴；新增的產碼／解碼器未出現在該回報。不以這點推定沒有安全風險。未執行會跨主要版本甚至降版的自動修復，需另行確認可利用性、修補版本與完整回歸，作為上線前門檻。
