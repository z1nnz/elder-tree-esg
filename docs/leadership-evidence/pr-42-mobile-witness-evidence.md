# 手機到場足跡與自願回饋：串接紀錄

日期：2026-08-28。[合併請求 #42](https://github.com/z1nnz/elder-tree-esg/pull/42) 仍為草稿；這份紀錄包含程式串接、自動測試及網頁執行的 Flutter 畫面，不代表原生實機、現場試辦或整個計畫已完成。

## 本次實作

- 雷達旅程保留 `requiresVenueWitness`，舊資料未帶欄位時預設關閉。地圖旅程面板及旅程卡的到場操作都進入獨立見證頁，完成後可再次開啟紀錄與回饋。
- 掃描現場碼或貼上短效碼後，成員另按「確認位置，留下足跡」。重新取得定位，拒絕原生定位服務標示的模擬位置、過期／不準確的位置及範圍外資料；不呼叫地圖的開發定位替代流程。
- 程式送出與後端相同的巢狀見證資料；後端仍為最終權威。沒有有效見證的合作旅程不能沿用按一下完成的舊流程。
- 領取與成長分開：不自動申請領取碼。成員自願開啟時，先更新領取狀態，再產生最長五分鐘的碼；以伺服器相對時間及單調時鐘扣除請求耗時。
- 碼不寫入網址或本機儲存；離開 App、切換樹伴圈或離開畫面即收起，晚到回覆不重新顯示。返回 App 時重新查詢紀錄，不自動產生新碼。
- 相機等待權限時若離開畫面，清理流程會等待啟動結束再停止和釋放。實際裝置相機生命週期仍需測試。
- 旅程完成後的首頁等次要資料更新失敗，不抹除伺服器已完成的結果；連點不重複送出完成請求。

## 設計與平台界線

使用「隨屏舒展」的閱讀寬度及自然捲動原則：內容最大寬度 600、獨立頁面、安全區、大字不縮小，沿用正式 App 主題。後續同日以「介面匠心」整理完成紀錄、自願回饋及補充說明，實際畫面與驗收界線見下方追加紀錄；原生相機及定位仍待確認。

原生掃描沿用已安裝的 `mobile_scanner@7.2.0`，目前開放 Android／iOS／macOS；網頁及其他桌面平台提供貼上現場碼的入口，不臨時下載外部網頁解碼程式。領取碼以固定的 `qr_flutter@4.1.0` 本機繪製，使用方式依據[套件官方文件](https://pub.dev/documentation/qr_flutter/4.1.0/)。鎖檔只新增該套件及 `qr@3.0.2`，沒有順便升級原有依賴。

## 建置與剩餘驗收

本機 Flutter 3.41.7 起初缺少 `const_finder.dart.snapshot`，正式網頁建置因此失敗。使用同版本 `flutter precache --web --force` 補齊工具，沒有升級 SDK 或停用圖示裁切。另一次建置與測試同時執行自動 `pub get` 時，曾出現 Apple 暫存套件目錄無法移除；沒有刪除或修改權限，而是在已成功取得依賴後，以 `--no-pub` 避免重複重建。最終 `flutter build web --release --no-pub` 成功產生 `build/web`，圖示裁切正常完成；`flutter analyze --no-pub` 無問題。

仍須完成：原生手機實際畫面、領取碼過期的實機顯示、相機權限生命週期、真實定位、跨裝置「夥伴台產碼 → 手機完成 → 夥伴台核銷」及弱網路回復；完整審查完成前不合併正式主分支。不能由這些測試推定商家已合作、實物已交付或真實生命樹已種植。

### 視覺取捨

這一頁的工作是讓成員確認「足跡已留下」，再自行決定是否領取小額回饋。延續品牌的森林綠 `#176B4A`、暖白 `#FFFDF7`、墨色 `#17201C` 與次要文字 `#536159`；以一道森林綠紀錄邊線連結共同年輪，不另外增加漸層、裝飾卡片或動畫。標題採既有中文字體與較重字級，日期與說明保留正常可讀字級。

- 原本置中的勾選圖示與完成文字分離，現在整合成一張有實際到場時間的紀錄；回饋放在另一段，不混成領獎才能完成。
- 首屏保留「不需要消費，也不必領取回饋」；詳細見證界線放入可展開說明，沒有刪除限制或藏進隱私條款。

- 領取碼到期後收起並顯示可重新開啟的提示；以向上取整顯示有效秒數，避免還有不足一秒時就讓畫面提早消失。
