## 在同行成林怎麼使用

先讀 [`CONTEXT.md`](../../CONTEXT.md) 與[品牌準則](../brand-guidelines.md)，再根據工作選最少的技能組合。不要讓多套技能各自替產品發明不同的視覺語言。

1. **定清楚畫面的工作**：誰在用、現在要完成什麼、唯一主要操作是什麼。例如共行旅程頁優先回答「輪到誰、要做什麼、怎麼接棒」，不是堆滿統計卡片。
2. **建立辨識度**：用既有品牌與「介面匠心」處理資訊層級；以樹伴圈的共同旅程、季節與真實紀錄作主角。需要比較方案時先出局部方向，不為了使用技能而全面換色、換字型或改架構。
3. **落實到平台**：Flutter 用「隨屏舒展」，遇到限制或溢出再用「版面修整」。網頁沿用現有元件與樣式，完工後用「網頁體驗巡檢」。不要把 React、SwiftUI 或 Compose 範例直接當 Flutter 實作。
4. **以真實畫面驗收**：保存修改前後截圖、尺寸、字級、操作結果與測試命令。程式檢查通過與畫面真的可用分開記錄。

### 不變的產品與無障礙底線

- 文字使用繁體中文共同語言；不把使用者介面改成英文術語展示。
- 不強制增加多套字型、漸層、玻璃效果、粒子、巨大宣傳數字或每區都包一張卡片。裝飾要能說明與群體旅程的關係。
- 長者不是兒童：語氣有尊重，操作明確，次要說明可展開，不以羞辱、失去連續紀錄或同伴壓力催促參與。
- 不用縮小字體、限制系統字級、隱藏溢出或裁切關鍵資訊來通過版面檢查。Flutter 主要觸控目標採至少 48×48 邏輯像素的專案基準；不把它宣稱為跨平台通用法規。
- 免費陪伴與共行核心維持完整；需要消費的優惠必須清楚標示且自願。年輪進度、成樹準備與已完成真實植樹分開呈現，不用示範數字冒充正式成果。
- 優先用原生語意與既有元件；不因技能出現工具或套件名稱就新增依賴、下載字型、升級 SDK、部署服務或回傳資料。
