# 以全螢幕 Unity 場景呈現生命樹庭園

Flutter 繼續負責樹伴的主要操作流程、樹伴圈、旅程、地圖、文字資訊與無障礙介面；Unity 只負責獨立的全螢幕「生命樹庭園」。Blender 保存可編輯模型母稿並輸出 FBX，Unity 負責即時渲染、枝葉風動、紀念物掛載與後續成長轉場。既有 Flutter 二維生命樹保留為低階裝置、降低動態效果、載入失敗及尚未支援平台的替代畫面。

## 採用理由

- 生命樹需要枝幹、前後葉冠與十二個穩定紀念掛點分層活動，三維場景比在 Flutter 畫布上持續增加模擬層更容易建立可維護的美術管線。
- Unity 作為程式庫在行動平台採全螢幕渲染，不適合嵌在 Flutter 頁面的一小張卡片；因此生命樹是可進入、可返回的獨立頁面，而不是取代整套 App。
- Flutter 的一般介面更適合長者友善文字、表單、地圖、輔助科技與平台原生權限；不為了單一三維畫面重寫整套產品。
- Blender 母稿、固定名稱階層及輸出腳本可以在共同開發時重現資產，避免只留下無法追溯的單一模型檔。

## 資料邊界

- Unity 不自行累積成長、不接受本機按鈕直接新增紀念物，也不保存可替代後端的進度。
- Flutter 只把已由 API 讀回的成長階段、紀念物識別碼、種類、色彩、掛點及降低動態偏好傳入場景。
- 資料契約版本第一版為 `1`；成長階段只接受 `0` 至 `5`，紀念掛點只接受 `0` 至 `11`，識別碼與掛點不得重複。
- 不合法、未知版本或衝突資料整筆拒絕並保留上一個可用狀態，避免畫面把錯誤資料呈現成真實成果。

## 動畫與無障礙

- 主幹保持穩定，主枝低頻小幅擺動，前景葉冠幅度略高；紀念物跟隨固定掛點，不以隨機位置漂移。
- 系統開啟降低動態效果時，非必要風動完全停止並回到基準姿勢，不使用閃爍替代。
- 成長階段、紀念名稱與成果來源仍由 Flutter 提供可讀文字；三維物件不是唯一資訊來源。
- 第一個垂直切片只有一棵成熟樹的正式階層。早期階段暫以保守顯示比例驗證資料管線，不能宣稱六套成長輪廓已完成；六階段各自模型與轉場須另行驗收。

## 效能與發布門檻

- 行動裝置先以每秒 30 幀為目標，枝葉使用分組物件與低頻程序動畫；後續建立材質合批、層級細節與記憶體量測。
- 不把 Blender 固定視角圖當成手機即時渲染證據，也不把 Unity 編輯器成功匯入當成 Android／iOS 整合完成。
- 合併 Flutter 串接前，必須至少驗證：Unity 編譯與編輯器測試、場景階層、降低動態、錯誤資料拒絕、Android 實機或安裝包，以及 iOS 可建置性。
- Unity 行動程式庫可能在卸載後仍保留一部分記憶體；Flutter 必須提供載入失敗及記憶體不足時的二維替代路徑。
