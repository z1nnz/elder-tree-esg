# 以場域內連續樣本建立複合行程見證

第三級行動見證不採「抵達一次即完成」，也不把探索工作階段的全部時間、距離或步數直接算入篇章。每次定位事件由伺服器判斷目前與前一個樣本是否都在指定場域；只有兩點皆在場域、時間依序、間隔不超過 120 秒、定位精度與移動速度合理時，才累加該段的停留秒數與距離。步數使用使用者主動授權的 Apple 健康或 Health Connect 唯讀總數，只累加同一有效場域區間的差值。

## 採用理由

- 單次地理圍欄命中只能證明一個時間點，無法證明曾在場域內完成一段行程。
- 工作階段總時間會把離開場域、斷線與 App 暫停時間誤算成停留。
- 工作階段總步數會把前往場域或離開場域後的步數算入篇章。
- 伺服器保存遞增進度與不可重複完成狀態，可避免重新安裝 App、重送事件或切換裝置造成重複年輪。
- 使用健康資料彙總值，不上傳心率、睡眠、診斷或逐筆健康紀錄。

## 規則

- 複合篇章必須是地理圍欄，且最低停留秒數、步數、場域內距離皆為正整數。
- 第一輪試辦把後台範圍限制為停留 30–3600 秒、步數 50–20000、距離 20–20000 公尺，避免誤設成瞬間完成或無法完成的極端篇章；擴大範圍須以試辦資料另作決策。
- 兩個連續場域內樣本的間隔上限為 120 秒；超過時以目前樣本重新建立錨點，不補算空白期間。
- 步數不得倒退，增加速度不得超過每秒五步加十步容差；異常事件整筆拒絕。
- 三項門檻全部達成才建立 `COMPOSITE` 層級的真實足跡並完成篇章。
- 工作階段結束或四小時逾時後清除最後精確座標、工作階段步數總量與來源；長期只在粗略定位回執及篇章見證保存必要的粗略區域、累計進度、資料來源與完成時間。
- API 在使用者操作時會立即清理逾時工作階段；常駐服務另每分鐘清理一次，因此 App 關閉後也不依賴下一次請求才清除精確座標。

## 邊界

第一版只能證明伺服器接受的定位樣本與裝置健康資料彙總共同符合規則。Android 健康資料來源不一定能完全辨識所有手動輸入紀錄，且客戶端回報仍不等於硬體級防竄改。因此本層級不可直接用於優惠核銷、志工時數、企業永續成果、成樹準備或真實植樹；高價值成果仍須短效現場碼、合作單位確認或其他更強見證。
